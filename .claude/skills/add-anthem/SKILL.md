# Add an anthem (or any arranged piece) to the site

Everything on the site is generated by `build/` from **adjiebrotot/anthem-orchestra**; never write `docs/` pages by
hand. One command does the work once the piece's metadata exists: `build/add.py`. This skill is the checklist
around it. Read `CLAUDE.md` (rules, lessons) first.

## 0. Once per machine (about 2 minutes)

```bash
python3 -m venv ~/.anthem-venv && ~/.anthem-venv/bin/pip install verovio==6.4.1 mido Pillow
(cd build && npm install)
git clone --depth 1 https://github.com/adjiebrotot/anthem-orchestra ../anthem-orchestra   # the branch with the piece
git clone --depth 1 https://github.com/adjiebrotot/orchestra ../orchestra                 # SoundFont (public, real file)
PY=~/.anthem-venv/bin/python
```

If the arrangement is not on anthem-orchestra's default branch yet, check out its branch
(`git -C ../anthem-orchestra fetch --depth 1 origin <branch> && git -C ../anthem-orchestra checkout FETCH_HEAD`).

## 1. What anthem-orchestra must already have (per slug, e.g. `indonesia-anthem`)

- `work/<slug>/song.json`, `analysis.json`, `guide.json` (+ `lyrics-map.json` for sung words) and
  `output/orchestra/<slug>.mid`;
- an entry in `work/youtube/anthems.py` (country, title, native, music, words, adopted, language, about, orch,
  region): the page title, description, FAQ and JSON-LD come from it;
- a `DESCRIPTIONS.md` overview row and section (key, meter, length, parts, character).

A piece that is not an anthem works the same way: give it those files and an anthems.py entry (country = the name
shown, e.g. a region or "Sample").

## 2. Three small rows in this repo (the preflight lists exactly which are missing)

```bash
$PY build/add.py <slug> [<slug> ...] --preflight
```

| Where | Row | Notes |
|---|---|---|
| `build/rights.py` `RIGHTS` | `'<slug>': (PD or CR, holder or None, year of the tune)` | PD (composer dead 70+ years, or an official symbol outside copyright) makes the arrangement CC BY-SA 4.0; CR asks only for credit (CC BY 4.0). Unsure: CR. Add `COMPOSER` / `LYRICIST` rows when anthems.py's music/words text does not read as a name ("students of ...", "written collectively": `''`) |
| `build/pages.py` `FLAGS` | `'<country slug>': '<iso code>'` + `docs/assets/img/flags/<code>.svg` | `npm pack flag-icons@7.5.0`, copy `package/flags/4x3/<code>.svg` (Wikimedia answers 429). Never an emoji flag |
| `build/i18n.py` `LANG_OF` (+ `WORDS`) | `'<slug>': '<lang>'` | Local-language search words for the titles and descriptions (GEO/SEO: "ноты скрипка Гимн России"). A new language needs a `WORDS` table: sheet, full score, orchestra, melody, the word order people search in, and the 18 instruments. English pieces need no row |

## 3. Build, check, publish

```bash
$PY build/add.py <slug> [<slug> ...] --soundfont ../orchestra/assets/soundfont/Pawchestra.sf3
```

It runs, and stops with a clear message at the first failure:
1. `check.py notes --only`: every engraved note against the arrangement (must be 0 mismatches);
2. `build.py --only` (creates the country folder, copies the MIDIs, engraves MEI, A4 page counts, share image);
   on "no loudness for this MIDI yet" it runs `node build/synth.mjs` once and builds again;
3. `check.py site`: links, JSON-LD, sitemap, score and player files (must say "site ok").

What the build writes for SEO/GEO, with nothing to do by hand: `<title>`/description with the native title and
local-language words, canonical, Open Graph/Twitter share image, JSON-LD (WebPage, MusicComposition with composer,
lyricist, licence, inLanguage, BreadcrumbList, FAQPage), `sitemap.xml` with image entries, `llms.txt`, and the home
page card and search entry.

Then:
- **Whole-site changes** (FAQ wording, home grid, "more anthems" cards of other pages): run the full build
  `$PY build/build.py --orchestra ../anthem-orchestra` (about 10 min) instead of `--only`.
- **Drop churn** before committing: a rebuild rewrites untouched `.mei.xml` files with new random ids (and the
  `#id` references to them) and a timestamp: restore those (snippet below). A full build also re-renders every
  share image: `git diff --name-only -- '*.png' | xargs git checkout --` for anthems whose notes did not change.
- **Look at it**: `python3 -m http.server -d docs 8765`, open `/<country>/`, `/<country>/melody/` and one
  instrument page in Playwright (route `cdn.jsdelivr.net` to a local `npm pack verovio@6.4.1` if offline); press
  play and click a note.
- Commit `build/` and `docs/` on a branch, push, open a PR (GitHub Pages publishes `main` / `docs`).
- Append the run's lessons to `CLAUDE.md`.

```python
# restore .mei.xml files whose only change is new ids (and the ids they reference) or the timestamp
import re, subprocess
def norm(s):
    s = re.sub(r'xml:id="[^"]*"', '', s)
    s = re.sub(r'#[A-Za-z0-9]+', '#', s)
    return re.sub(r'\d{4}-\d\d-\d\dT[\d:.]+', '', s)
fs = subprocess.run(['git', 'diff', '--name-only', '--', '*.mei.xml'], capture_output=True, text=True).stdout.split()
n = 0
for f in fs:
    old = subprocess.run(['git', 'show', f'HEAD:{f}'], capture_output=True, text=True).stdout
    if norm(old) == norm(open(f).read()):
        subprocess.run(['git', 'checkout', '--', f]); n += 1
print(len(fs), 'changed .mei.xml,', n, 'restored (ids only)')
```

## Rules that bite

- Never rename a published country slug, instrument slug or file name (search engines index them).
- No PDFs or page images in `docs/` (the browser draws and prints the score).
- Page copy is plain English with no em-dashes (`check.py site` flags them).
- Never claim to have listened to the playback; report what the checks say.
